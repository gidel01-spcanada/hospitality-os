# Admin back-office: amenities catalog

Area: UAT-PROP (030-036). Source of truth: `AdminAmenityController`, `routes/web.php` (group `admin`, lines 236-264), `resources/views/admin/amenities/*`, lang `flash.amenity_*`, `errors.amenity_category_in_use`.
Access: admin only. Host and concierge receive 403 ("Administrator access is required.").

## UAT-PROP-030: Amenity catalog access and category list
- **Feature / journey:** `/admin/amenities` catalog overview
- **Priority:** P1
- **Role / permissions:** Admin (allowed); Host, Concierge, Customer (403)
- **References:** `admin.amenities.index`; `AdminAmenityController::index`; `resources/views/admin/amenities/index.blade.php`
- **Preconditions / setup:** Catalog seeded with several categories and amenities (`ReferenceDataSeeder`/amenity migrations).
- **Test data:** Admin and host accounts.
- **Steps and expected results:**
  | # | Action | Expected result |
  |---|--------|-----------------|
  | 1 | Admin opens `/admin/amenities` | Categories ordered by `sort_order`, each with its amenity count. |
  | 2 | Open a category (`/admin/amenities/categories/{id}`) | Amenities of the category in order, with edit/delete actions. |
  | 3 | Host and concierge open `/admin/amenities` | 403. |
  | 4 | Logged-out visitor | Redirect to `/login`. |
- **Acceptance criteria:** Catalog is visible only to admins and counts match data.
- **Evidence to capture:** Screenshots, count comparison with DB.
- **Notes / assumptions / open questions:** Amenity routes do not use `{amenity}` tenant scoping in the controller; isolation depends on model global scopes (multi-tenant only). In multi-tenant testing, check that tenant B's admin does not see tenant A's categories.
