## Defects

1. **Reservations accepted on unpublished, inactive or inactive-establishment properties** (UAT-PUB-021). Severity guess: High. `PublicPropertyController@reserve` has no published/active guard (show and availability have one). Repro: as a verified customer POST `/properties/uat-draft/reserve` with CSRF token and valid dates. A pending reservation is created and you are redirected to checkout. Anonymous submits create unverified customer accounts.
2. **No server-side capacity check on public booking** (UAT-PUB-037). Medium. POST `/properties/uat-apt-a/reserve` with adults=5 (or 3 adults + 2 children) on a max_guests=4 property creates the reservation. The availability endpoint also ignores capacity.
3. **Checkout never displays error flashes** (UAT-I18N-008). Medium. `resources/views/checkout/show.blade.php` renders only `session('status')`, so every `with('error', ...)` from CheckoutController is dropped silently (for example 'Payment is awaiting confirmation.'). Repro: start pay_later, then GET `/reservations/{id}/checkout/pay_later/return`.
4. **Feedback mail failure returns HTTP 500 after the row is saved** (UAT-FEED-004). Medium. `PlatformFeedbackController@store` creates the row, then calls `Mail::send` synchronously with no error handling. Repro: unreachable SMTP, POST `/feedback`. The user gets a 500 page and a retry duplicates the row.
5. **Login page gives no explanation after the booking form redirects there** (UAT-PUB-029). Low/Medium. The `auth.existing_account_login` status flash is never rendered by `auth/login.blade.php`. Repro: submit the booking form logged out using an existing verified customer email.
6. **Hard-coded French date validation messages in English mode** (UAT-I18N-007, also seen in UAT-PUB-032). Low. Repro: `/language/en`, then submit the booking form with a past check-in or with check-out before check-in.
7. **419 and 429 error pages ignore the visitor language** (UAT-PUB-061). Low. The pages are always French because these errors are raised before the route `locale` middleware runs. Repro: `/language/en`, then POST any form without a CSRF token.
8. **Compare currency-mismatch 422 page hides the explanatory message** (UAT-PUB-009). Low. `errors/422.blade.php` shows generic text only. Repro: `/properties/compare?properties[]=<XOF id>&properties[]=<EUR id>`.
9. **Establishment page has no "view all reviews" link** (UAT-PUB-011). Low. Repro: open `/establishments/afrik-appart-cotonou`, which has reviews. No `/reviews` link is present.
10. **Preferences save shows no confirmation and invalid-value errors are not displayed** (UAT-I18N-005). Low. The flash `status` is set on the redirect to `/dashboard`, but the dashboard never shows it. `/account/preferences` does not render `$errors`.
11. **Booking form phone field has no accessible label** (UAT-A11Y-002). Low. `input#phone` has a placeholder only. Related: the menu button's `aria-controls="mobile-nav-actions"` points to an id that does not exist (UAT-A11Y-001, recorded as a static finding).

Observations, not counted as Fail:
- Search and listing validation errors are never shown to the user, because the redirect has no error output (PUB-003, PUB-006).
- The availability JSON for `available:false` still carries the 'dates are available' message (PUB-024).
- A brand-new email gets the 'account already exists but never confirmed' wording (PUB-028).
- `/reserve` has no throttle (PUB-030).
- A staff user's public booking is linked to the staff user_id (PUB-036).
- The iCal export omits pending-type reservations that block the website (CAL-003).
- The iCal export has no DTSTAMP and no VALUE=DATE (CAL-001/005).
- The public calendar route has no throttle (CAL-002).
- `CalendarFeedSyncService::sync` re-enables disabled feeds (CAL-004).
- The help chat widget is hidden entirely when no API key is set (HELP-001/003).
- The help-chat system prompt uses literal `\n` sequences (HELP-002).
