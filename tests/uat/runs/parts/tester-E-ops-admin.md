## Defects

- D1. External event UID is unique across all feeds (`external_calendar_events.uid` has `->unique()` in `2026_08_22_000004_create_system_and_admin_tables.php`). Cases: CALA-002, INT-030 (seen while adding feeds). Severity: P1. Repro: add two feeds (same or different property) whose ICS share a UID (for example the same channel calendar). The second sync fails "SQLSTATE[23000] UNIQUE constraint failed: external_calendar_events.uid" and the feed stays stale. The full SQL text and DB path are shown to the admin.
- D2. Cross-tenant admin access to property calendar tools and export. Cases: CALA-012, INT-028. Severity: P0. Repro: as an admin of tenant 2, GET `/admin/properties/1/calendar`, `/calendar/feeds/create`, `/calendar/export.ics` and `/admin/properties/1/edit` of tenant 1. All return 200.
- D3. SSRF and unbounded fetch on calendar feed URLs. Case: INT-030 (also CALA-002). Severity: P1 security. Repro: save an enabled feed with `http://127.0.0.1:<port>/x.ics`, `http://localhost:...` or a URL that 302-redirects to loopback. The server fetches it. A ~50 MB body causes a 500 (memory exhausted) and leaves the feed `syncing`. Credentials in the URL are stored plaintext and shown in the edit form.
- D4. Cleaning visit edit page returns 500 for visits linked to a reservation (`Call to undefined method Eloquent\Builder::orWhereKey()` in `CleaningScheduleController::edit`). Cases: CLN-004 (also seen in CLN-003, AUD-005). Severity: P1. Repro: create a visit with a reservation, open `/admin/cleaning/{id}/edit`.
- D5. Manual "Sync" shows the success flash "Calendar feed sync completed." even when the sync failed. Cases: CALA-003, INT-023. Severity: P2 usability. Repro: point the feed to a 500 URL and press Sync. The flash says success while the status is stale with an error.
- D6. A manual Sync silently re-enables a deliberately disabled feed, and its events start blocking. Cases: CALA-008, INT-025. Severity: P2 (pending PO).
- D7. Validation errors are not displayed on admin index pages (cleaning schedule, cleaning share, reports, global reviews and CSV import, audit logs). `layouts/admin.blade.php` renders only `session('success'|'status'|'error')`, and these index views do not render `$errors`. Cases: CLN-001, CLN-007, RPT-002, AUD-002, REVA-001, REVA-003, INT-032. Severity: P2. Repro: `/admin/reports?date_from=2027-01-01&date_to=2028-01-02` redirects back with no message.
- D8. Generate-from-departures skips departures on the last day of the period on SQLite (`whereBetween('check_out', [from, to])` compares `2026-12-06 00:00:00` with `2026-12-06`). Cases: CLN-006 (affected CLN-010). Severity: P1 (on SQLite; verify on MySQL). Repro: confirmed reservation with a Sunday check-out, generate for that week. No visit is created.
- D9. Public cleaning schedule cannot be shown in English: the `/cleaning-schedule/*` routes have no `locale` middleware, so `?lang=en` has no effect. Case: CLN-008. Severity: P2.
- D10. Reports accept `date_from` later than the default `date_to` and render a negative period ("-547 day(s)"). Case: RPT-002. Severity: P3. Repro: `/admin/reports?date_from=2028-06-01`.
- D11. CSV/formula injection in report export: a property named `=SUM(1+1)` is written unescaped. Case: RPT-005. Severity: P2 security candidate.
- D12. Cleaning schedule list does not show visit instructions. Case: CLN-002. Severity: P3.
- D13. Establishment review update and delete are not scoped to the establishment in the URL (IDOR). Case: REVA-002. Severity: P1 security. Repro: as host of E1 only, PUT or DELETE `/admin/establishments/1/reviews/{id of an E2 review}`. The change is applied.
- D14. Booking.com import from the admin UI is not idempotent: re-import inserts duplicates ("2 added, 0 updated"). The importer looks up with `tenant_id = null` while saved rows get the tenant id. The CLI, which passes the tenant, does update. Cases: REVA-004, INT-033. Severity: P1 (data quality).

## Environment notes

- `vendor/` lacks `barryvdh/laravel-dompdf` (declared in composer.json/lock), so every PDF route returns 500 ("Class Barryvdh\DomPDF\Facade\Pdf not found"). The CLN-008 PDF step could not be verified. Other agents' receipt PDF cases will hit the same issue.
- The instance's PHP `upload_max_filesize` is below 5 MB, so files over 2-5 MB fail with "failed to upload" before the app's `max:5120` rule. Rejection still happened.
- `storage/logs` (laravel.log, error-YYYY-MM-DD.log) is shared by all instances. The admin log viewer showed other testers' entries (mail log bodies with reset/checkout links). AUD-004 S6 (empty dir) was not run to avoid touching shared files.
- The app accepted loopback feed and review-source URLs, so all integration fixtures were served locally (`127.0.0.1:9105`). HTTPS fixtures were not used.
- Tooling limits: no browser (visual calendar widget, copy buttons, JS confirms and calendar-client subscription not observed), and no Excel (RPT-005 S3).
- The reports dataset was placed in June/August 2028 to isolate it from other data. User locales in this DB were set to `en`, and FR checks switched the admin user to `fr` temporarily.
- State changes: only instance 5's DB (`db5.sqlite`) plus shared log lines. No files were written under `public/uploads`. Fixtures and scripts live under `%TEMP%\uat-run\fixtures-E` and `%TEMP%\uat-run\E-s`. The fixture server on port 9105 was stopped at the end.
